# v1.4.0 (2026-07-10)

Production-readiness wave on top of v1.3.0 (13 feature/test commits,
`d8b85e5..22f1d89`, plus a QA fix round). Migrations **0035-0037** ship
with this release (all idempotent; no destructive DDL - 0035 deletes
photo rows that violate the new stock-only invariant).

## Features

- **Computed public holidays** ([[holidays]]) - the static 2026-2028
  `public_holidays` seed is replaced by `holiday-service.ts`: Gauss
  Easter, all 16 Bundesländer (incl. Buß- und Bettag SN, documented
  communal-only exclusions), company Bundesland resolved from free-text
  `company_settings.state`, federal-only fallback. Consumers: calendar
  grid, absence workday math, public-API free slots. The table is now
  dormant (future drop candidate).
- **SMTP Testversand** ([[smtp-mail]], [[settings]]) -
  `sendSmtpTestMail` with 10 s transport timeouts and curated German
  error classes (DNS / connection refused / auth / TLS / timeout /
  rejected recipient / missing config); never recorded in
  `sent_messages`; per-process 5 s double-fire guard (429) on the
  remote; `SmtpTestSend.svelte` below the SMTP form at `/settings/smtp`
  with a dirty hint for unsaved edits.
- **eBay customer detection on import** ([[kfz-kaufmann-import]]) -
  `isEbayCustomerName` (case-insensitive substring "ebay" over
  Name/Firma/Vorname/Nachname) classifies customers as `kind='ebay'`
  during the Kfz-Kaufmann import only; no runtime auto-logic, no
  historic rewrite; documented false-positive class ("Ebayer"/"Sebayn"
  yes, "Bayer" no).
- **PDF engine hardening + visual regression** ([[pdf-pipeline]]) -
  WinAnsi sanitizing at every draw/measure boundary, exact greedy
  wrapping (`wrapTextLines`), row-level page breaks with repeated table
  heads, measured totals block (moves whole to a continuation page),
  per-rate MwSt lines for mixed-tax invoices, rendered Kopftext +
  discount notes, "Seite X von Y" on every page, byte-deterministic
  renders. New `pdf-visual.test.ts`: 15-fixture snapshot matrix via
  `pdftoppm` + a pure-node pixel differ; committed PNGs under
  `__pdf_snapshots__/`; refresh with `PDF_SNAPSHOTS=update`.
- **Order ↔ invoice rule set with Storno cycle**
  ([[order-invoice-rules]]) - one active invoice per order
  (`getActiveInvoiceForOrder`), permanent `documents.work_order_id`
  backlink (migration 0037 with backfill), item lock under an active
  invoice, `done` only via `completeWorkOrder` (Kanban drops rejected),
  cancel auto-reopens the order, billed orders and order-linked
  invoices undeletable (GoBD), invoice-history card on the order
  detail.
- **Employee absences completed (Teil-A spec)** ([[employees]]) -
  server-computed, holiday-aware workday counts (the client never does
  day math), year-scoped balance, hard vacation-budget gate per touched
  calendar year (unlimited when no entitlement is configured),
  canonical overlap semantics (same-type hard 400, vacation↔sick 409 +
  replace-confirm on create, 'other' never conflicts), half-day
  (single-day only), testable `AbsenceSection` component.
- **Vehicle stock invariants** ([[vehicles]]) - photos and
  Verkaufsschilder are stock-only (`customer_id IS NULL`,
  server-enforced 409s); galleries are sales artifacts (deleted on
  sale, Ankauf starts empty; migration 0035 cleanup); archived vehicles
  cannot be angekauft. Calendar cleanup: no order-creation shortcut in
  the calendar view; the Termin form carries two separated cross-module
  cards (Werkstattauftrag / Urlaub & Krankheit).
- **eBay Phase 2 - Trading API listing import** ([[ebay]]) -
  `GetMyeBaySelling` import with an injectable transport, idempotent
  sync keyed on `(environment, ebay_item_id)` with ended/revive
  semantics, new tables `ebay_listings` + `ebay_import_runs` (migration
  0036), import card + paginated listings table at `/settings/ebay`,
  curated German error map, token material never logged. Phase 3
  (bidirectional tire sync, listing-tire matching) stays deferred per
  [[adr-014-ebay-two-way-sync-deferred]] (the `tire_id` FK is
  prepared).
- **Tabs/UI standard** ([[styling]]) - `TabGroup.svelte` is the one
  app-wide tab implementation (tabs-lift radio pattern, `?tab=` deep
  links, nav mode); settings flattened to own routes
  (`/settings/mail|reminders|smtp`, legacy `?tab=` redirects); detail
  pages tabbed: customers (Übersicht/Fahrzeuge/Rechnungen/Aufträge),
  vehicles (Übersicht/Halter/Rechnungen/Aufträge/Fotos/Dokumente/
  Historie) with `CompactCustomerCard`; vehicle Historie merges
  purchases (rename-proof snapshot), sales (live link) and plate
  versions. Rule: content switching = TabGroup, list filters = simple
  filter tabs; no nested tabs anywhere.

## Testing

- Full Vitest suite: **2051 passed + 1 skipped across 140 files**
  (`pnpm test`); component library at **250 tests** incl. new
  `AppShell` (19) and `PdfViewer` coverage.
- Real Playwright E2E suite: **55 tests in 12 spec files, ~30 s**
  against the committed anonymized fixture DB
  (`e2e/fixtures/seed.sql.gz`) - navigation, customers, vehicles, the
  full order-invoice storno cycle, employees and absences, calendar,
  settings (incl. legacy-redirect and SMTP click-time validation),
  users and permissions, hours, PDF viewer, module smoke. New
  hydration- and navigation-safe helpers (`gotoHydrated`,
  `fillFieldVerified`, `pickFromSearchablePicker`, `clickDialogButton`,
  `openDetailTab`) and a GoBD-respecting self-cleaning strategy. See
  [[test-database]].

## Fixes (QA round)

- `formDirty` is cleared only after a **successful** save - failed
  saves keep the unsaved-changes guard armed.
- `WorkOrderForm` no longer overwrites a hand-typed title when a
  customer/vehicle is picked.
- All modals use the native `<dialog>.showModal()` (focus trap, Esc);
  `ConfirmDialog` catches a rejecting `onConfirm`.
- `Pagination` ellipsis buttons are truly disabled.
- Work-order status labels consolidated into
  `src/lib/utils/status-labels.ts` (`workOrderStatusLabel` /
  `workOrderStatusBadge`).
- Absence mutations fixed to real single-flight: the client declares
  `.updates(...)`; server-side `requested(...).refreshAll()` alone
  never refreshed the client (see [[remote-functions]]).
