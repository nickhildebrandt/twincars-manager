# TwinCast — Production-Readiness Work Package

Living plan for taking TwinCarsManager to a first productive deployment at
**TwinCast** (Kfz-Werkstatt with tire trade + used-car side business).
This file is the cross-session source of truth: keep the status boxes
current as work lands.

## Binding direction decisions (2026-06-22)

1. **Permission model → full per-module.** One permission key per module
   (`customers`, `vehicles`, …) instead of `:read|:write|:delete`. Refactor
   every `*.remote.ts` guard, the seeded roles, the role matrix UI, and the
   permission tests. Keep the `hours:write_own` special case for employees
   logging only their own time, and `import:run`.
2. **eBay → deferred.** Do NOT implement now. Full spec lives in
   [`ebay-integration.md`](./ebay-integration.md) for a later package.
3. **`discontinued` (Auslaufartikel) → removed entirely.** Drop the column
   and every filter on items + tires. Tire shop visibility is governed by
   `onlineSellable` alone. `stockMin`/`stockMax` (Soll-/Mindestbestand) are
   removed too. Tire `stockOnHand` stays (eBay sync + local overview).

## Sequencing rationale

pnpm first (toolchain), then shop-refocus (unblocks clean import routing),
then permission refactor (mechanical, isolated), then import hardening
(highest risk, depends on shop-refocus), then setup + tire-storage +
search + UI audit. Tests are written alongside each phase, not at the end.
