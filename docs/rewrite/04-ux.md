## 1. Leitlinie

Die Nutzererfahrung bleibt in **Aufbau und Verhalten sehr nah am Bestand**.
Informationsarchitektur, Navigation, Routen und Abläufe bleiben erkennbar
dieselben. Die Bedienerinnen und Bediener sind nicht technisch; sie sollen die
neue Anwendung ohne Umlernen benutzen können.

**Abweichungen gibt es nur dort, wo ein Befund aus
[02-befunde.md](02-befunde.md) sie begründet.** Jede Abweichung ist in §10 mit
Befund-ID aufgeführt. „Schöner in Nuxt UI" heißt: dieselbe Struktur, besser
umgesetzt — nicht neu erfunden.

Der Charakter der Oberfläche bleibt: **flach, umrandet, ruhig**. Keine
Schatten im Inhaltsbereich, keine gestrichelten Rahmen, keine Zebrastreifen,
eine einzige Akzentfarbe. Die Daten sollen sprechen, nicht die Hülle.

## 3. Verbindliche Muster

### 3.1 Toasts — für jede Mutation, Erfolg wie Fehler

- **Jede** schreibende Aktion endet sichtbar: Erfolgs-Toast oder Fehler-Toast.
  Kein stiller Erfolg, kein stiller Fehlschlag. Das gilt auch für
  Hintergrund-artige Aktionen wie „Jetzt prüfen" oder Sortierwechsel mit
  Speicherung.
- Alle Toasts laufen über `useNotify()`. Direkte `useToast()`-Aufrufe sind
  verboten, damit Wortlaut und Dauer nicht auseinanderlaufen.

| Art     | Farbe     | Dauer                          | Beispieltext                                                                 |
| ------- | --------- | ------------------------------ | ---------------------------------------------------------------------------- |
| Erfolg  | `success` | 4 500 ms                       | „Kunde gespeichert."                                                         |
| Fehler  | `error`   | 8 000 ms, mit Schließen-Aktion | „Kunde konnte nicht gespeichert werden: Die Rechnung ist bereits versendet." |
| Hinweis | `info`    | 4 500 ms                       | „Keine fälligen Erinnerungen gefunden."                                      |
| Warnung | `warning` | 6 000 ms                       | „3 von 12 Empfängern konnten nicht erreicht werden."                         |

- Fehlertexte sagen, **was zu tun ist**. „Es ist ein Fehler aufgetreten" allein
  ist unzulässig, wenn der Server einen kuratierten Grund liefert.
- Mehrere Toasts dürfen sich stapeln (höchstens drei gleichzeitig, neueste
  oben). Der Bestand ersetzt einen Fehler-Toast sofort durch den nächsten
  Erfolgs-Toast, sodass Fehler übersehen werden (B-115).
- Erfolgs-Toasts nach einer Navigation erscheinen auf der **Zielseite**, nicht
  auf der verlassenen.

### 3.2 Animationen — flüssig, kurz, abschaltbar

Feste Werte, damit es überall gleich aussieht. Sie stehen einmal in
`app/app.config.ts` bzw. als Tailwind-Token in `main.css`.

| Vorgang                | Dauer                     | Kurve                           | Bewegung                        |
| ---------------------- | ------------------------- | ------------------------------- | ------------------------------- |
| Seitenwechsel raus     | 120 ms                    | `cubic-bezier(0.4, 0, 1, 1)`    | Deckkraft 1 → 0, 4 px nach oben |
| Seitenwechsel rein     | 180 ms                    | `cubic-bezier(0.16, 1, 0.3, 1)` | Deckkraft 0 → 1, 6 px von unten |
| Layoutwechsel          | 180 ms                    | wie oben                        | nur Deckkraft                   |
| Modal öffnen           | 200 ms                    | `cubic-bezier(0.16, 1, 0.3, 1)` | Skalierung 0,96 → 1 + Deckkraft |
| Modal schließen        | 140 ms                    | `cubic-bezier(0.4, 0, 1, 1)`    | rückwärts                       |
| Hintergrund (Backdrop) | 160 ms                    | linear                          | Deckkraft                       |
| Slideover              | 220 ms rein / 160 ms raus | wie Modal                       | Verschiebung von rechts         |
| Toast                  | 200 ms rein / 140 ms raus | wie Modal                       | 8 px + Deckkraft                |
| Dropdown, Popover      | 120 ms                    | ease-out                        | 4 px + Deckkraft                |
| Zeilen-Hover           | 80 ms                     | linear                          | Hintergrundfarbe                |
| Ladebalken             | fortlaufend               | —                               | oben, überlagert die Kopfleiste |

- **`prefers-reduced-motion: reduce` wird respektiert.** Dann gilt: alle
  Dauern 0 ms, keine Verschiebung, keine Skalierung; Deckkraftwechsel bleiben
  erlaubt, weil sie kein Bewegungsempfinden auslösen. Ein Browsertest prüft
  das ([05](05-teststrategie.md) §4.3).
- Keine Animation darf das Layout verschieben oder eine Eingabe verzögern.
  Der Ladebalken reserviert keinen Platz im Fluss.

### 3.3 Ladeanzeige — drei Stufen wie bisher

| Stufe | Auslöser                  | Anzeige                                                                                                     |
| ----- | ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1     | jede laufende Anfrage     | dünner Balken oben (`<NuxtLoadingIndicator>`), die **einzige** Ladeleiste der Anwendung                     |
| 2     | Klick auf eine Aktion     | der Button zeigt einen Spinner und ist für die Dauer der Anfrage gesperrt (Schutz gegen Doppel-Submit)      |
| 3     | Anfrage länger als 250 ms | halbtransparente Sperrfläche über dem Inhaltsbereich, `aria-busy`; Sidebar und Kopfleiste bleiben bedienbar |

Verboten bleiben: eine zweite Ladeleiste irgendwo, Skelett-Ansichten auf
Detailseiten, lokale `busy`-Flags.

### 3.4 Pagination — serverseitig, fix 25

- Jede Liste lädt serverseitig, 25 Einträge je Seite, **kein Größenwähler**.
- Fußzeile: links „N Treffer · Seite X von Y", rechts die Blätterleiste
  (erste, zurück, fünf Zahlen, vor, letzte).
- Filter-, Such- oder Tabwechsel setzt immer auf Seite 1 zurück.
- Beim Blättern bleibt die vorige Tabelle stehen, bis die neuen Zeilen da sind.
- Kein unendliches Scrollen, kein clientseitiges Zerschneiden einer bereits
  geladenen Liste.

### 3.5 Mehrfachauswahl — immer im modalen Dialog

Wie im Bestand: Mehrfachauswahl (z. B. zugewiesene Mitarbeiter an einem
Auftrag, Empfängerkreis eines Rundschreibens) öffnet einen **modalen Dialog**
mit serverseitiger Suche, Pagination und Kontrollkästchen. Der Dialog ist
**transaktional**: „Übernehmen (N)" schreibt die Auswahl zurück, „Abbrechen"
und ein Klick auf den Hintergrund verwerfen sie. Die Auswahl übersteht einen
Seitenwechsel innerhalb des Dialogs.

### 3.6 Beziehungen auswählen — nie ein `<select>`

Jede Verknüpfung auf einen anderen Datensatz (Kunde, Fahrzeug, Artikel,
Mitarbeiter, Lieferant, Auftrag) läuft über den **`EntityPicker`**: ein Feld,
das wie ein Eingabefeld aussieht, einen Dialog mit Serversuche öffnet, 250 ms
entprellt, serverseitig paginiert und eine „×"-Schaltfläche zum Leeren hat.
Feste, kurze Wertelisten (Anrede, Saison, Zahlungsart) bleiben ein `<select>`.

Fehlt der gesuchte Datensatz, bietet der Dialog **genau eine** Schaltfläche
„Neu anlegen" in der Kopfzeile. Sie führt auf die reguläre Anlegeseite; der
Entwurf des aufrufenden Formulars wird zwischengespeichert, nach dem Anlegen
wiederhergestellt und der neue Datensatz automatisch ausgewählt. Verschachtelte
Abläufe (Auftrag → Fahrzeug → Kunde) sind erlaubt, eine Schleife auf denselben
Typ nicht. Keine Mini-Formulare im Dialog.

### 3.7 Zustände — für jede Liste und jede Detailseite definiert

| Zustand                        | Liste                                                                                                       | Detailseite                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Leer (nie Daten)**           | Karte mit Satz „Noch keine Kunden angelegt." + Primäraktion „Kunde anlegen"                                 | Karte mit „Für dieses Fahrzeug sind noch keine Dokumente hinterlegt." + Aktion                   |
| **Leer (Filter ohne Treffer)** | „Keine Treffer für Ihre Suche." + „Filter zurücksetzen" — **im Bestand fehlt diese Unterscheidung** (B-186) | —                                                                                                |
| **Laden (erstmalig)**          | Kopf und Filterleiste stehen, Tabellenbereich zeigt drei ruhige Platzhalterzeilen                           | serverseitig gerendert, kein Zwischenzustand                                                     |
| **Laden (Nachladen)**          | vorheriger Inhalt bleibt, nur der Balken oben zeigt Aktivität                                               | dito                                                                                             |
| **Fehler**                     | Karte mit deutscher Meldung + „Erneut versuchen"                                                            | ganzseitige Fehlerkarte mit „Zurück" und „Zum Dashboard"                                         |
| **Keine Berechtigung**         | Seite ist gar nicht erreichbar; die Middleware leitet auf eine erklärende 403-Seite, Sidebar-Eintrag fehlt  | Nebenkarten, für die das Recht fehlt, werden ausgelassen — **die Seite fällt nicht aus** (B-337) |

### 3.8 Formulare

- **Speichern wird nie wegen fehlender oder ungültiger Eingaben deaktiviert.**
  Nur eine laufende Anfrage oder ein echter Modus-Riegel (gesperrte
  Systemrolle) darf sperren.
- Geprüft wird **beim Klick**: alle Felder als berührt markieren, deutsche
  Fehlerzusammenfassung oben, Fehler am Feld, Fokus auf das erste fehlerhafte
  Feld. `novalidate`, damit keine englischen Browserblasen erscheinen.
- **Schutz gegen Doppel-Submit**: Der Button sperrt sich für die Dauer der
  Anfrage und zeigt einen Spinner.
- **Warnung bei ungespeicherten Änderungen** beim Verlassen der Seite und beim
  Schließen des Browserfensters. Die Markierung wird **vor** der Navigation
  nach dem Speichern gelöscht, sonst bricht der Bestätigungsdialog die
  Navigation ab (bekannte Fehlerklasse des Bestands).
- **Ein geleertes Feld wird geleert gespeichert.** Im Bestand bleibt der alte
  Wert stehen (B-183, B-221) — der wohl ärgerlichste Fehler für die täglichen
  Nutzer.
- Jedes Eingabefeld hat ein sichtbares Label, Pflichtfelder tragen eine
  Markierung, jedes Feld füllt die Breite seiner Rasterzelle.

### 3.9 Tabellen und Detailnavigation

- Tabellen zeigen nur die nützlichsten Spalten; alles Weitere steht auf der
  Detailseite.
- **Die ganze Zeile ist anklickbar** und führt zur Detailansicht. Aktionszellen
  am Zeilenende schlucken den Klick.
- Summenzeilen stehen im Tabellenfuß und sind optisch abgesetzt.
- Auf schmalen Geräten wird die Tabelle zu einer Kartenliste; dieselben
  Informationen, dieselbe Klickfläche.

### 3.10 Bestätigungen

Zerstörerische oder nach außen wirkende Aktionen (Löschen, Archivieren,
Stornieren, Versenden, Import) verlangen einen Bestätigungsdialog mit
konkretem Text: was passiert, womit, und ob es umkehrbar ist. Beispiel:
„Rechnung R-2026-0042 stornieren? Es wird eine Stornorechnung erzeugt. Der
zugehörige Auftrag wird wieder geöffnet. Das lässt sich nicht rückgängig
machen."

## 5. Listen und Detailseiten im Einzelnen

### 5.1 Liste

Aufbau von oben nach unten: Seitentitel mit Primäraktion rechts · Filterleiste
in einer Karte · Tabelle in einer Karte · Blätterleiste im Kartenfuß.

Neu gegenüber dem Bestand (begründet durch B-196): **Filter, Suche, Tab und
Seite stehen in der URL**. Damit funktioniert die Zurück-Taste, ein Link auf
eine gefilterte Liste ist teilbar, und ein Neuladen verliert den Zustand
nicht. Das ist die einzige strukturelle Änderung am Listenverhalten.

### 5.2 Detailseite

Kopf mit Bezeichnung, Status-Badge und Aktionen · Übersichtskarten ·
Registerkarten für die Nebenbereiche (Fahrzeuge, Rechnungen, Aufträge,
Dokumente, Historie). Registerkarten spiegeln sich weiterhin in `?tab=`.
**Die Detailseite zeigt alles** — was in der Datenbank steht und fachlich
bedeutsam ist, ist sichtbar; der Nutzer muss nirgends suchen.

## 6. Sprache und Ton

- Oberfläche vollständig auf **Deutsch**, Siezen (der Anredestil für Kunden
  ist getrennt davon in den Firmeneinstellungen konfigurierbar).
- Fachbegriffe wie im Betrieb: „Beleg", „Zahlungserinnerung", „Ankauf",
  „Reifeneinlagerung", „Kostenvoranschlag".
- Schaltflächen sind Verben: „Speichern", „Anlegen", „Archivieren",
  „Stornieren", „Per E-Mail senden".
- Fehlermeldungen nennen Ursache und nächsten Schritt, nie einen Statuscode,
  nie einen Dateipfad, nie SQL.

## 8. Zugänglichkeit

- Jede Aktion ist mit der Tastatur erreichbar; die Reihenfolge folgt der
  optischen Ordnung.
- Modale Dialoge fangen den Fokus, schließen mit Escape und geben den Fokus an
  das auslösende Element zurück. Im Bestand gilt das nur für einen Teil der
  Dialoge (B-104 ff.).
- Jedes Bedienelement hat einen zugänglichen Namen; Suchfelder ebenso
  (im Bestand teilweise nicht).
- Statusinformationen werden nicht allein über Farbe vermittelt.
- Kontrast mindestens 4,5:1 für Text.
- Toasts werden als `aria-live` angekündigt.

## 9. Golden Flows

Diese fünfzehn Abläufe müssen am Ende als End-to-End-Test grün sein
([05-teststrategie.md](05-teststrategie.md) §4.5). Sie decken zusammen den
Alltag des Betriebs ab.

| #        | Ablauf                          | Kurzbeschreibung                                                                                                     |
| -------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **G-01** | Ersteinrichtung                 | Leere Datenbank → Assistent in sechs Schritten → erster Administrator → Dashboard                                    |
| **G-02** | Anmelden und abmelden           | Anmelden, falsches Passwort, gesperrtes Konto, Abmelden, Weiterleitung auf das ursprüngliche Ziel                    |
| **G-03** | Kunde vollständig               | Anlegen → in der Liste suchen → bearbeiten (inkl. Feld leeren) → archivieren → im Archiv wiederfinden → reaktivieren |
| **G-04** | Fahrzeug mit Halter             | Fahrzeug anlegen, Halter über den Picker wählen, Kunde aus dem Picker heraus neu anlegen, zurückkehren, speichern    |
| **G-05** | Auftrag bis Rechnung            | Auftrag anlegen, Mitarbeiter zuweisen, Positionen erfassen, Kanban-Spalte wechseln, abschließen → Rechnung entsteht  |
| **G-06** | Rechnung versenden und bezahlen | PDF ansehen, per E-Mail senden (Mail-Catcher), als bezahlt markieren, im Ausgangsbuch prüfen                         |
| **G-07** | Storno-Zyklus                   | Rechnung stornieren → Stornorechnung öffnet sich → zugehöriger Auftrag ist wieder offen                              |
| **G-08** | Angebot zu Rechnung             | Angebot anlegen, versenden, in eine Rechnung wandeln, Positionen und Preise vergleichen                              |
| **G-09** | Zahlungserinnerung              | Offene Rechnung überfällig machen, „Jetzt prüfen", Erinnerung senden, Eintrag unter „Gesendet"                       |
| **G-10** | Termin und Auftrag              | Termin im Kalender anlegen, Auftrag daraus erzeugen, Termin am Auftrag sehen                                         |
| **G-11** | Zeiterfassung                   | Stunden als Mitarbeiter mit Selbstservice-Recht buchen, fremde Einträge sind unsichtbar, Monatsbericht stimmt        |
| **G-12** | Fahrzeughandel                  | Kundenfahrzeug ankaufen, Fotos hochladen, Verkaufsschild erzeugen, über eine Rechnung verkaufen                      |
| **G-13** | Reifeneinlagerung               | Einlagerung anlegen, Etikett erzeugen, QR-Ziel öffnen, Erinnerung versenden                                          |
| **G-14** | Buchhaltung                     | Buchung erfassen, Liste filtern, Summen prüfen, DATEV-Export herunterladen                                           |
| **G-15** | Benutzerverwaltung              | Benutzer anlegen, Rolle zuweisen, Rechte in der Sidebar prüfen, Benutzer deaktivieren → Sitzung endet                |

Zusätzlich als Integrationslauf (ohne Browser): **Öffentliche Schnittstelle** —
Bearer-Token, freie Slots abrufen, Termin buchen, Kontaktanfrage senden,
Gebrauchtwagen und Reifen abrufen.

## 11. Was ausdrücklich gleich bleibt

Damit niemand in Versuchung gerät, es „besser" zu machen:

- Acht Sidebar-Gruppen, gleiche Reihenfolge, gleiche Namen, gleiche Icons.
- Registerkarten auf Detailseiten, Einstellungen als Navigations-Tabs.
- Kanban mit drei Spalten für Aufträge.
- Kalender als Monatsraster mit Terminliste.
- Assistent mit sechs Schritten für die Ersteinrichtung.
- Fester Seitenumfang 25.
- Ein einziger Farbakzent, flache Karten mit Rahmen.
- Deutsche Oberfläche, englischer Code.
